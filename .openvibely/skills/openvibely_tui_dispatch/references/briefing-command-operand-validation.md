# Briefing Command Operand Validation

Use this reference when inspecting or changing the project-scoped briefing commands `/pulse`, `/reflection`, `/grades`, and `/insights` in `internal/tui/registry.go`, including their headless CLI paths.

- Treat each command's action grammar as strict. After the project guard and action normalization, accept only the documented action for that command (`show` plus the command-specific `summary`, `run`, or `analyze` action) and require that no operands remain. An unknown action or surplus operand must return the command's existing usage/error form rather than falling through to the default read or regeneration path.
- Validate the complete operand list before starting any backend work. In particular, malformed input such as `pulse nonsense` must not perform the normal read, and `pulse summary extra` must not trigger regeneration or its follow-up fetch. In CLI mode these failures must produce a nonzero result; in interactive mode they should use the established local usage guidance. Both paths must issue zero HTTP requests for invalid input.
- Keep the valid default and explicit-action behavior unchanged. For trigger-and-fetch actions, retain the side-effect-only trigger followed by exactly one content read, and test the request order separately from invalid-operand rejection.
- Add a table-driven dispatch/CLI matrix for every briefing command's default form, each supported action, an unknown action, and one or more surplus operands. Assert the error/exit behavior, zero requests for invalid cases, and the existing trigger-then-fetch sequence for valid regeneration cases. Include a regression for both an unknown action and an extra operand because they can otherwise fail through different fallthrough paths.
- When reproducing a suspected parser defect with a temporary HTTP server, verify that the server actually started and capture both the process exit code and received requests. A failed harness connection is not product evidence; only a successful request trace should establish that malformed input reached the application.
