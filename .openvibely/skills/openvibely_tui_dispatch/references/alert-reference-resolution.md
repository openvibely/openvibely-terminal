# Alert Reference Resolution

Use this guidance when implementing or auditing `/alerts read`, `approve`, `reject`, `dismiss`, or `delete` reference matching.

- Keep canonical alert identity fields separate from optional searchable text. Resolve an exact ID first, then an exact case-insensitive visible title, before title-prefix, title-substring, or body/search fallback.
- Do not pass `title + " " + body` as the alert's name to a generic tiered matcher. That demotes a typed visible title from an exact match; with `Deploy` and `Deploy service`, a valid `Deploy` reference can otherwise become an ambiguous prefix.
- Use an alert-specific resolver that invokes normal standalone ID/title matching first. Only run a searchable-text fallback when that matcher specifically reports no match, not when it reports ambiguity. Preserve duplicate exact-title, prefix, and text-search ambiguity errors rather than guessing.
- Route all five action paths through that resolver in both interactive TUI and headless CLI modes. Keep `alerts show` behavior independent unless the command is intentionally migrated and separately covered.
- Keep alert IDs, titles, searchable text, and typed references raw until resolution completes. For ambiguity and not-found errors, use `matchRefWithDisplay` (or equivalent) with a presentation-only callback; never sanitize the values or reference before matching.
- Use one alert-specific single-line display helper for backend-controlled canonical titles/IDs and typed references in confirmations, CLI `--force` guidance, success status lines, and match diagnostics. It must strip ANSI/OSC and nonprinting controls and replace line breaks, carriage returns, tabs, and Unicode line separators with spaces. Fall back from a blank sanitized title to the sanitized ID, then a stable placeholder.
- For typed interactive `alerts delete <ref>`, resolve the reference asynchronously before calling `confirmOr`. Capture the resolved stable ID and sanitized canonical display title in the pending command; never defer list lookup or matching until after the user enters `yes`.
- Selector deletion is safe only when its callback also captures the selected alert's ID. Use the same canonical display helper for selector confirmations and mutation status; do not use selector safety to justify a typed-reference path that stores a closure over raw input or rereads the catalog after confirmation.
- Missing or ambiguous typed references must show no confirmation, and `--force` failures must make no mutation request. A unique partial reference may prompt only after resolution, with the canonical target named in the prompt. After a prompt, a changed catalog must not rebind the eventual DELETE from the captured ID.
- Add regressions with `Deploy` and `Deploy service`, non-empty body text, and mixed title casing. Cover every action, exact-title precedence, duplicate exact-title ambiguity, unique body/search fallback, ambiguous body/search fallback, and zero mutations for all failed resolutions in interactive and headless paths.
- Assert raw, pre-renderer output is terminal safe for ANSI/OSC, NUL and other C0 controls, newline, carriage return, and hostile references. Cover matcher diagnostics, interactive confirmation and success status, plus headless `--force` guidance. Do not strip ANSI in the fixture or before the safety assertion; separately prove readable sanitized text remains and raw matching semantics are unchanged.

For implementation changes, run `gofmt` on changed Go files, then `go build ./...`, focused `go test ./internal/tui -run '<tests>' -count=1`, `go test ./... -count=1`, `go vet ./...`, and `git diff --check`. When async resolution or confirmation paths change, run the narrowest relevant `internal/tui` tests under `-race`; expand to `./...` only when behavior crosses package boundaries or the task explicitly requires it.
