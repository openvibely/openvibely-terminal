# Interspersed Global CLI Flags

Use this checklist when changing one-shot CLI parsing or `RunCLI` dispatch in `openvibely-tui`, especially when global options must work on either side of a command or subcommand.

- Do not feed raw interspersed arguments directly to Go's standard `flag.FlagSet`: parsing stops at the first positional token. Instead, scan the registered global options, stably move only recognized globals ahead of the command operands, and invoke the standard parser once. Keep command dispatch generic rather than adding a `chat`-specific exception.
- Recognize the exact registered global vocabulary only. Preserve command-local flags and dash-prefixed positional operands for the command parser; do not consume every token beginning with `-`. Unknown global options before the command must retain the established error, while tokens that belong to a command must remain available to that command's validation.
- Match Go's one- or two-dash forms precisely: normalize `-name` and `--name` to the same registered name, but do not strip an arbitrary number of dashes. Handle both separate values and `--name=value`, including boolean globals and compatibility aliases such as `-json`/`--json`, without changing operand order.
- Treat `--` as an explicit end-of-options boundary. Do not extract or reinterpret global-looking tokens after it. Preserve every non-global token, including quoted shell arguments and multi-word messages, exactly as the process received it; never join and re-tokenize the argument vector.
- Preserve existing duplicate-flag, malformed-value, unknown-flag, help, project-resolution, and backwards-compatibility behavior. Help must remain a local, backend-free path even when requested after a command; command-local parsing must continue to own its local flags and errors.
- Test at two levels. Add table-driven parser tests for globals before, between, and after command operands, boolean/value/`=value` forms, aliases, boundaries, duplicate and unknown flags, local-looking operands, and exact positional preservation. Add HTTP-backed `RunCLI` dispatch tests that assert the actual command, quoted message, resolved project ID, JSON mode, and representative non-chat subcommand behavior.
- Finish with `gofmt`, `go build ./...`, `go vet ./...`, uncached `go test ./...`, and a built-binary help smoke test that captures both stdout and stderr because Go's flag package writes help to stderr. Use `git diff --check` and verify no backend worktree was modified.
