# Selector Safety And CLI Parity

Use this guidance whenever a command builds an interactive selector from local files, backend records, or other untrusted metadata.

- Route missing-reference behavior through `selectorOr` (or an equivalent explicit CLI/TUI branch). Interactive TUI mode may fetch and open a picker, but headless CLI mode must return a nonzero usage error before selector setup or selector data fetching. Test the actual `RunCLI` path, not only the command handler, because an active selector can otherwise produce no output and be mistaken for success.
- Treat selector rows and selection-echo transcript entries as independent output surfaces. Sanitize ANSI and terminal control characters and bound labels, details, and displayed references before rendering or echoing them; list/show/search renderers cannot protect values inserted by generic selector code. Keep a canonical safe reference separate from its sanitized display text so display cleanup never changes the file or resource dispatched.
- Preserve partial-result warnings when converting a list into selector items. Missing or malformed index state must not be silently converted into a generic empty-state claim, and an indexed-but-unavailable document must be presented as unavailable/read failure rather than as an empty document.
- Keep initial and typed selector filtering on the same `matchSelectorItems` path so case-insensitive label, detail, and reference matching cannot drift. Compute or reuse the search cache once, call the helper only for a non-empty initial filter, and preserve the original item slice for an empty filter. Do not move auto-selection, `forcePicker`, warning, pending-command, prefill/cursor, cache, or dispatch lifecycle behavior into the matcher while deduplicating the scan.
- Add focused regressions for a missing ref in both modes, selector labels/details/refs containing ANSI, control characters, and oversized text, warning-bearing empty/partial indexes, and missing or non-regular selected entries. For filter-path changes, also cover case-insensitive label/detail/reference parity, empty-filter slice identity, zero/multiple results, unique auto-selection, and forced-picker behavior. Assert no unintended backend or filesystem request occurs before the CLI usage error and no unsafe value reaches the transcript.

These checks apply equally to compatibility aliases and to selectors that auto-select one item, because the single-item selection message also echoes data before dispatch.
