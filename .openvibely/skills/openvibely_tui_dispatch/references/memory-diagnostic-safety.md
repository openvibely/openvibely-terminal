# Memory Diagnostic Safety

Use this when implementing or reviewing indexed project-memory lookup and TUI/CLI error rendering.

- Keep canonical indexed handles separate from every display or diagnostic value. Canonical handles may be used only for validated path resolution and dispatch; never interpolate raw indexed filenames directly into ambiguity errors, selector labels, warnings, transcript entries, or other terminal-facing text.
- Treat indexed filenames and titles as untrusted input even after parsing. Reject NUL and all Unicode control characters in handles at the normalization boundary, and keep path validation independent from display sanitization.
- Build ambiguity diagnostics through one helper. Sanitize control characters, bound each candidate, cap the number of candidates, append a concise omission count, and bound the final error. Preserve enough of the first candidates to make disambiguation useful without allowing terminal escape sequences or unbounded index content to reach `error.Error()` and the generic model error sink.
- Treat an explicit document availability/state field as authoritative in renderers. Do not infer successful availability from an empty body or from the absence of warnings: cancellation, deadline, and other failed reads may have no warning text. Render `(empty memory file)` only when the document explicitly reports available and its body is empty; render unavailable for every explicit unavailable result, including no-warning errors.
- Add focused regressions with ANSI/control-bearing handles and an oversized set of long candidates. Assert no `unicode.IsControl` runes, a finite rune bound, useful candidate context, safe warnings, and rejection before selector/dispatch. Keep canonical valid-handle lookup coverage separate from diagnostic rendering coverage. Include an unavailable-document case with `Available:false`, empty body, and nil/empty warnings to prevent compatibility fallbacks from relabeling failures as empty content.
- After changes in this area, run `gofmt`, `go build ./...`, `go vet ./...`, `go test ./... -count=1`, and `git diff --check` when the repository supports them. Add focused race-detector coverage only if concurrent index refresh, loading, or shared state changes.
