# CLI Reference And Option Parsing

Use this skill when adding or auditing CLI/TUI commands shaped like `<resource-ref> <option> <value> [...]`, especially when references may be names, titles, quoted strings, multiword substrings, or confirmation-gated mutation targets.

## Procedure

1. Classify each action by its own grammar before finding a reference boundary. If an action accepts no options, treat every token after the action as the reference and do not run a shared option-boundary parser. Resolution will then reject surplus or malformed option-like tails while still allowing canonical names that contain tokens such as `--enabled maybe`.
2. Treat option keywords and their values as ambiguous with valid resource text. Do not identify the reference boundary solely by scanning for the first option-name token or the first syntactically valid option/value pair.
3. Evaluate every potential trailing-option boundary against both option syntax and the actual resource collection when the command contract permits discovery. Retain successful parses and rejected suffixes with their exact validation errors; do not discard an invalid earlier suffix merely because a later suffix parses successfully.
4. Resolve candidate references with the command's established precedence, such as exact ID, exact name, unique prefix, then unique substring. Apply that precedence globally across parse boundaries, not independently followed by an unranked conflict check: an exact canonical ID must beat a competing title match from another boundary.
5. Do not let an early candidate that parses valid pairs or yields an ambiguous short reference force an error before later boundaries are tested. A resource title may contain complete valid-looking pairs such as `repeat daily`, `interval 4`, `clear-context false`, or `run-at 2026-01-22T10:30`, including at the end of the title.
6. Compare all successful and candidate-bearing outcomes by match tier. If several equally ranked valid boundaries uniquely resolve to the same resource, choose the longest reference boundary so the most title text is preserved and only the true trailing suffix supplies updates. If equally ranked valid boundaries uniquely resolve to different resources, report boundary ambiguity rather than guessing. Do not let lower-tier matches override higher-tier matches or higher-tier candidate-bearing ambiguity.
7. If a malformed suffix follows a reference that resolves, preserve its specific validation failure unless a later valid boundary legitimately resolves the expanded text with equal-or-stronger matching evidence as resource content. Inputs such as `<id> repeat yearly interval 5`, an invalid timestamp followed by a valid pair, duplicate settings followed by a valid pair, or surplus operands before a valid pair must not be silently reinterpreted.
8. Translate request-timing requirements literally. If acceptance says malformed input must fail "before any request," syntax validation must complete locally and tests must assert zero collection, detail, and mutation requests. Do not weaken that requirement to "before detail or mutation" merely because collection discovery simplifies title-boundary resolution.
9. When strict zero-request validation conflicts with supporting unquoted titles containing option-like text, surface the contract conflict and choose an explicit deterministic grammar or product rule. Do not silently add a discovery exception, ID-shape heuristic, or test expectation that contradicts the stated timing requirement.
10. When discovery is explicitly permitted, ordinary title references may require one resource-list lookup to determine whether an earlier malformed suffix belongs to a real title. After that lookup, fail before resource-detail lookup or mutation when the malformed suffix applies. ID-shaped references may sometimes be rejected earlier when identity is locally conclusive, but do not use ID-shape heuristics as the general correctness rule.
11. Preserve the strongest resource-resolution evidence across all boundaries instead of returning whichever error was seen last. In particular, an earlier candidate-bearing ambiguity must not be overwritten by a later `nothing matches` result; within the same tier, prefer the longest candidate for a more specific ambiguity message.
12. Reject malformed option tails, duplicate options, missing values, and invalid values at the earliest boundary required by the command contract. In headless mode, do not issue prohibited collection, detail, or mutation requests after parse, validation, or reference ambiguity failures.
13. Quoting may preserve shell token grouping but must not be required to avoid collisions between title words and option keywords unless the documented grammar explicitly chooses quoting to satisfy a strict local-validation contract.
14. If an explicit reference/options separator is needed, verify it survives every outer parser before documenting it. A conventional `--` may be consumed by a global flag parser and never reach command dispatch; prefer an established command-local delimiter such as `|` when that is the repository grammar, document shell quoting or escaping, and test the real executable argument parser as well as direct dispatch. A resolving left prefix and valid suffix make a separator interpretation viable, not automatically authoritative: also evaluate whether the same token is a literal option value in another complete valid parse, then rank both interpretations with the normal global reference precedence. In particular, an exact canonical ID literal-value parse must beat a longer project-name interpretation around `|`. Completion must model the separator as a literal continuation after the free-form/deep-wildcard reference, not as content swallowed by that wildcard.
15. Build one canonical accepted-value set for enums and compatibility aliases, then reconcile every user-facing and execution surface against it: parser validation, normalization, generated usage/help, completions, examples, interactive dispatch, headless dispatch, and client serialization. An alias accepted by execution but omitted from help or completion is incomplete support, even when lower-level client tests prove normalization.
16. For confirmation-gated mutations, resolve the reference before constructing the pending confirmation or applying the headless `--force` gate. Ambiguous and unknown references must return their matching errors immediately, while a unique partial reference must use the resolved resource's canonical name in the prompt or force guidance.
17. Capture the resolved canonical object in the deferred mutation closure rather than matching the raw reference again after confirmation. Cancellation must issue no mutation, confirmation must use that exact object, and transport-specific endpoint mapping must remain in the client layer.
18. Account for CLI startup preflight ordering. If invalid references must fail before any request but project discovery happens before dispatch, add a local/static reference validator in the argument-validation phase when the candidate set is known without I/O. Keep normal dispatch resolution as the execution source of truth for valid inputs.
19. Treat every reference-resolution diagnostic as terminal output. Sanitize and bound the user-supplied reference plus all backend-controlled candidate names, keys, and IDs before composing unknown or ambiguity errors; do not rely on a later generic result/error renderer to make them safe.

## Regression Coverage

- For actions that accept no options, test unknown option-like tails, recognized option names with malformed or missing values, syntactically valid-looking option pairs, and exact resource names containing the same tokens. Run the matrix through interactive and headless paths; assert the full name resolves, invalid tails do not open confirmation, and no detail or mutation request targets the shortened reference.
- Test a resource whose entire name equals each option keyword.
- Test multiword names containing option keywords at the beginning, middle, and end.
- Test names containing complete syntactically valid option/value pairs for every option value class: timestamps, enums, bounded integers, and booleans.
- Test a name ending in a valid-looking pair and verify the longest exact reference wins over a shorter ambiguous prefix.
- Test an exact canonical ID boundary against a competing title boundary and verify the exact ID wins in interactive and headless paths.
- Test distinct equally ranked valid title boundaries that resolve to different resources and assert ambiguity before prohibited requests.
- Test each malformed option class followed by a later valid pair for both ID and ordinary-title references. Verify the specific malformed-option error wins.
- For a strict "before any request" contract, count every request class and assert collection GETs, detail GETs, and mutations are all zero in both interactive and headless tests.
- When collection discovery is explicitly allowed, assert title failures perform at most that discovery request and no detail lookup or mutation.
- Test an earlier ambiguous boundary followed by a later non-match and verify candidate-bearing ambiguity is preserved rather than replaced by the later no-match.
- Test quoted and unquoted forms, including the headless CLI path where supported.
- For explicit delimiters, test interactive tokenization, direct headless dispatch, completion after the delimiter, and the outer executable/global-flag parser. Cover a resource containing complete option pairs, a conflicting shorter resource, shell-preserved delimiter syntax, an unresolved non-empty prefix, and the delimiter token used as a legitimate option value before later options. Add a collision where the delimiter's left prefix resolves as a longer resource name while the complete grammar also resolves an exact canonical ID with the delimiter as its value; assert only the exact-ID target receives detail and mutation requests.
- Test resource names equal to global flags such as `--json`, `--force`, or `--project` through the executable's documented outer `--` boundary, not only through direct dispatch.
- Test ordinary IDs and names, duplicate or missing options, malformed tails, ambiguous references, and confirmation/selector paths.
- For destructive commands, cover ambiguous, unknown, unique-partial, canceled, confirmed, unforced, and forced cases. Assert canonical prompt/guidance text, matching-error precedence over force requirements, zero requests where required, and the exact mutation endpoint only after confirmation.
- Assert failures do not dispatch prohibited requests, not merely that an error string is returned.
- For every canonical enum value and accepted alias, add table-driven checks that help and completions advertise it, interactive and headless parsing accept it, normalization emits the backend value, and serialization sends that value. Do not treat client-only coverage as command-surface coverage.
- Inject ANSI/OSC sequences, bells, tabs, newlines, carriage returns, and other controls into both the typed reference and backend candidate metadata. Assert the raw interactive and headless ambiguity/unknown output is safe and retains its intended line structure before applying any display-normalizing test helper.
