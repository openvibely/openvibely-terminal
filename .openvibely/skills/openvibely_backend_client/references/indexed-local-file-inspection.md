# Indexed Local File Inspection

Use this guidance when a client reads project-local files whose names come from an index, manifest, or other external metadata, including repository-local managed memory.

- Verify the authoritative index and storage contract first. If no public backend list/read/search or curation route exists, keep the client read-only and derive inspectable entries only from the canonical project-local index; do not enumerate unindexed files or invent a second source of truth.
- Establish the selected repository as the trust root before joining any indexed handle. Reject empty, absolute, traversal, index-file, NUL-containing, and otherwise invalid references. Canonicalize the repository root and the memory directory, and reject a boundary directory symlink that places the inspected directory outside the canonical repository root; do not compare a target only with a symlink-resolved root that may itself point outside the repository.
- Make containment and file-type validation hold for the file that is actually opened. A separate `Stat`/canonical-path check followed by path-based `Open` is a TOCTOU gap: a concurrent replacement can turn a regular file into an external symlink or a blocking special file. Prefer descriptor-relative/no-follow or equivalent atomic open/read primitives where available, reject FIFOs, sockets, devices, directories, and other non-regular files before reading, and add replacement-race coverage on supported platforms.
- Bound index and document reads before parsing or rendering, preserve cancellation checks, and convert OS failures into safe bounded diagnostics that do not expose repository paths, secrets, or raw error bodies.
- Treat resolver diagnostics as terminal output too: sanitize indexed handles, titles, queries, and ambiguity candidates for control/ANSI sequences, normalize them to one line, and bound their size before embedding them in errors or warnings. Keep canonical raw handles only in internal dispatch data; do not rely on a generic TUI error renderer to sanitize client errors that may be appended verbatim.
- Keep parser behavior aligned with the authoritative writer/helper: recognize only explicit file-reference forms, do not treat prose that merely mentions `.md` as an entry, and surface malformed, empty, rejected, duplicate, missing, or unavailable entries as safe warnings while retaining usable partial metadata.

Focused regression coverage should include a repository-root or memory-directory symlink escape, target symlink escape, traversal and index references, FIFO/device/directory rejection without blocking, file replacement between validation and open, bounded/invalid input, and parser fixtures copied from the current backend writer. Plain and JSON callers should both verify safe diagnostics and non-nil collections.
