# Terminal Connection-Diagnostic Redaction

Use this guidance when adding or changing terminal-visible transport, backend-health, recovery, status, or login diagnostics.

- Send every terminal-visible error detail through the shared bounded terminal-safe diagnostic formatter; do not directly append `err.Error()` to recovery messages, model state, or `/status` rows.
- Strip terminal controls and line breaks before rendering, and cap the final display width. Preserve enough non-secret context, such as operation, network error, safe status, host, and path, to diagnose a failure.
- Normalize configured server URLs at the client boundary before requests or display: recognize `http://` and `https://` with ASCII case-insensitivity, then canonicalize only the scheme to lowercase. Do not prepend `http://` to a valid uppercase or mixed-case scheme, since doing so turns authority/userinfo into path data and defeats safe URL parsing.
- Redact every embedded HTTP(S) URL before generic credential masking. URL recognition must be case-insensitive (`HTTP://`, `HTTPS://`, and mixed-case schemes occur in configured values, wrapped `url.Error`, and backend error text). Parse the matched URL and remove userinfo, the entire query, and fragment while retaining the safe endpoint portion.
- Do not depend on query parameter names to identify URL secrets: even a harmless-looking key can contain sensitive data, so remove the complete query. Apply separate credential-assignment masking afterward for non-URL `token=`, `password:`, cookie, and similar fields.
- Authorization-header masking must consume the complete value, not just the header name or scheme. In particular, redact `Authorization: Basic <credential>` and `Authorization: Bearer <credential>` including their credentials, with case-insensitive scheme recognition; a replacement such as `Authorization:[redacted]` must never leave the next token visible.
- Add a client-level regression proving a mixed-case HTTPS configured URL makes a real request after normalization. Add raw-output regressions through every formatter/state that can expose the configured endpoint or error detail, including startup, setup, offline recovery, reachable-but-unhealthy recovery, and rendered `/status`. Use uppercase and mixed-case schemes with distinct sentinel values in userinfo, query, and fragment; assert all sentinels are absent while the expected safe host/path context remains. For reachable backend diagnostics and raw `/status`, include distinct Basic-auth, Bearer-auth, and generic token sentinels and assert each is absent before ANSI stripping.
- A model can retain `authRequired` from an earlier authentication response while a later connection check yields a transport error. Preserve sign-in state and login guidance, but branch that later recovery by configured endpoint: explicitly remote servers must first advise checking or correcting the remote URL and must never suggest local startup; local endpoints retain setup and local-backend-start guidance. Add a combined auth-required plus transport-failure status regression that asserts this ordering and absence of local-start copy for a remote endpoint.
- Styled `/status` output intentionally contains renderer-owned ANSI sequences. For configured-server sanitization, capture unstripped output and assert the exact injected untrusted control sentinel is absent; use separately stripped output for text assertions. A blanket no-escape assertion after stripping cannot prove the renderer removed untrusted input.
