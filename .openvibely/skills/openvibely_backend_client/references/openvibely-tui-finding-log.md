# OpenVibely TUI Finding Log

Use this reference when auditing or implementing OpenVibely TUI/backend-client parity, performance, bug, redundancy, or JSON-output work. Check current code and existing notifications before relying on a historical item.

## Open Findings To Recheck Before Filing

- `renderBoard` in `internal/tui/view.go` historically omitted the backend-supported `scheduled` task category, causing scheduled tasks to vanish from the board. Fix direction: render a `scheduled` column or otherwise include scheduled tasks, with a regression test for a project whose only tasks are scheduled.
- `GetWorkerSettings`, `GetChannels`, and `GetPersonality` historically duplicated the page-fetch/text-extract sequence that `pageText` already centralizes. Fix direction: rewrite them as thin `pageText` wrappers if the duplication is still present.
- Product suggestion `65a78e3acae6f83275f8df26a417e2cd` reports that project memory is invisible in the TUI: backend memory is stored under `.openvibely/memories`, initialized through `MEMORIES.md`, selected into task turns, and exposed to agents through `memory_view`, but the TUI command surface, client methods, docs, and structural command tests have no memory workflow. Fix direction: add a user-facing memory inspection/curation command surface backed by existing backend behavior, with command registry/help/client coverage.
- Product suggestion `7ef8a033f9cd1a110a12a5e2fa81dbdd` reports that task run logs are summarized in the terminal, but users cannot open the detailed task lifecycle execution event trace from the command surface even though lifecycle event fetching exists in the client/backend path. Fix direction: add a project/task-run scoped command or view to open lifecycle execution events, keep the lifecycle tab summary, and add command registry, dispatch, client, and regression coverage.
- Bug suggestion `bcb4063d6d9deb6c79dc43b440bf2a11` reports that `GetTask` can return a successful task detail while its concurrent lazy loads (`/tasks/:id/thread`, `/changes`, and lifecycle data) fail; `tasks show` then renders empty or omitted sections while the command result reports success. Fix direction: preserve and surface lazy request/decode errors, or expose an explicit partial-data state, instead of silently treating incomplete details as complete. Add focused regressions for main-detail success plus each lazy endpoint failure and the resulting command/status behavior.
- Bug suggestion `60b7d10e365898e515eb007f31803183` reports that the shared HTML/HTMX mutation transport treats every `3xx` response as success while an expired or missing session redirects to `/login`. Model deletion, alert actions, task mutations, and channel changes can therefore print success even though the backend rejected the write. Fix direction: classify login redirects as authentication failures in `doFormResponse` without breaking legitimate HTMX success responses, and add transport tests for `302`/`303` login redirects plus command regressions proving rejected writes do not produce success output.
- Authentication-recovery audit from task `2f5417c1200e3c4d496ad2134d4fa25` found that redirect classification using `strings.HasPrefix(Location, "/login")` falsely treats near-match paths such as `/login-help`, `/login2`, and `/login-redirect` as authentication. Fix direction: parse the `Location` URL and require the path to be exactly `/login` while allowing its query string; cover `401`, valid `/login?...`, near-match redirects, ordinary non-login redirects, and no-follow behavior across mutation transports.
- The same authentication-recovery audit found that configured-credential login preflight in `cmd/tui/main.go` can run before backend-independent help/usage dispatch and can return a generic wrapped login error for a refused or timed-out backend instead of the established offline recovery guidance. Fix direction: skip credential preflight for static help/usage paths, preserve typed login transport errors, and surface start/check-backend plus `-server`/`OPENVIBELY_SERVER_URL` guidance without exposing credentials; add CLI coverage for configured-credential transport failure and offline help.

Before creating a new actionable notification, call `list_existing_automation_notifications` and page through results. If a remembered notification ID no longer appears, treat it as likely completed or archived; use `get_alert` only for close candidates.

## Settled Patterns From Prior Fixes

- Project-scoped Alerts and Automations commands must reject an empty selected project locally before selector setup, confirmation, ref parsing, or backend calls; do not rely on backend fallback project selection. Cover list, read, mutation, and destructive actions with zero-request regression tests.
- Skill mutations must use the backend's JSON contract rather than browser form encoding. Preserve existing name, description, and enabled state during body-only edits, send the actual global/project scope, classify login redirects as authentication failures, and verify persisted state in addition to request shape.
- `channels list --json` must use live channel state/configuration rather than a hardcoded compile-time channel list. Every scraper-derived struct emitted by CLI JSON must have explicit lowercase or snake_case `json:` tags, with marshal tests asserting representative keys.
- Stream capped response bodies directly into parsers such as `html.Parse` when raw bytes are not needed. Preserve the existing response-body drain and close behavior.
- Deduplicate raw card nodes before expensive text extraction, and centralize repeated scrape/deduplicate call pairs behind a small private helper such as `dedupedCards`.
- Chained resource commands such as `/automations run-now|pause|resume|delete <ref>` should add client mutation methods matching existing backend HTMX routes, resolve refs with `matchRef`, reuse `refreshAndRender`, and cover exact/prefix/substring/ambiguous references plus backend failures.
- Widened enum keyword sets such as schedule repeat types should normalize synonyms through one helper and parse optional trailing numeric intervals without breaking old fixed-arity invocations. Validate repeat intervals against the backend `1..365` rule before posting; invalid values must make no mutation request.
- Slack channel removal uses `/channels/slack/disconnect`; other channel types use `/channels/<type>/remove`. Keep the route asymmetry explicit and covered by tests.
- Independent fetch fan-out in client/TUI code should use `sync.WaitGroup`, per-goroutine local result/error variables, and merge after `wg.Wait()`; add timing tests and run race tests.
- Mixed error semantics need separate all-sections and single-section paths. For example, analytics all-section fan-out can omit failed sections, while a single explicitly requested section should still return its error directly.
- SSE `chat_response_done` should trigger an immediate chat status fetch, or use a completed-output fast path when payload content is present. Keep the 1500ms polling loop as fallback only.
- SSE streams should pass the selected project ID into `StreamEvents`, and `chat_response_done` handling should ignore foreign project IDs before either fast path or status fetch.
- Duplicate public client methods that only differ by URL path segment should delegate to a private helper while keeping public signatures unchanged.
- `refreshAndRender` deliberately swallows refetch errors after a successful mutation and returns the success status. Preserve this policy consistently across consolidated mutation commands.
- One-shot `status` output that prefetched alert/task counts must not schedule the same count refresh again after rendering; each count source should be fetched once while output retains the prefetched values.
- When an HTML resource page exposes stable card attributes and the client already parses structured records, use those records for the normal list renderer, filters, action-reference resolution, and post-mutation refresh. Keep whole-document `NodeText` or `pageText` conversion as a prose fallback, extract only the needed ID/name/state and action attributes, and preserve the parser's prior state precedence for malformed cards. Test active and paused rows, full IDs, filtering, empty-state guidance, unchanged JSON shape, one-GET list behavior, and mutation refreshes.

## Validation Expectations
