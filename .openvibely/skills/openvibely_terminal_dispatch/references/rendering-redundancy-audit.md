# Rendering Redundancy Audit

Use this reference when auditing or implementing approved consolidation of duplicated presentation logic in `internal/terminal/view.go`.

- Compare the responsibility and emitted output at each production renderer, not just similar-looking commands. If multiple renderers independently produce the same section-heading plus dimmed `no data` empty state and only the section title varies, treat that as a real presentation duplication and propose one small private helper parameterized by the title or section data.
- Compare resource-page renderers with shared selector empty-list paths in `internal/terminal/selector.go`, not only renderers in the same file. Identical create/use guidance can be duplicated between a page and the picker opened for that resource; confirm the exact strings and owning symbols before reporting it, and distinguish this from a screen that merely lacks next-action guidance.
- Inventory repeated user-facing empty-state literals by exact string, then group only occurrences that implement the same responsibility. Name every production page/selector path in the finding and preserve intentionally different empty messages, resource-specific wording, and test-only baseline renderers.
- Keep the finding narrow when a broader action/reload duplication is already tracked elsewhere; do not re-report a covered generic pattern merely because another command exercises it. Likewise, a suggestion about missing hints does not cover a separate duplication where equivalent hints are already rendered in multiple surfaces.
- When the exact actionable hint is shared by a resource page and ref-less selector fallback, prefer one narrow unexported package-level constant per resource family and reference it from the page renderer and every corresponding selector branch. Audit action-specific branches independently; for example, automation selectors may have separate show/open and mutation paths. Do not introduce a generalized rendering abstraction for this string-only consolidation.
- For lifecycle task-history views, keep `renderLifecycleTaskHeading(task)` as the single private producer of the styled `title  (id ID)` line, with the existing `firstNonEmpty(task.Title, shortID(task.ID))` fallback. Have both `renderLifecycleExecutions` and `renderLifecycleEvents` call it, while leaving execution metadata, event tables, and renderer-specific empty states in their respective functions. Add focused coverage that compares the first heading from both renderers for titled and empty-title tasks and strips ANSI to verify the short-ID fallback.
- For an approved implementation, add focused table-driven regression coverage for every renderer and selector routed through the canonical definition. Exercise real no-item selector flows, compare both exact styled output and ANSI-stripped visible text so spacing, heading, dimming, and `no data` text cannot drift, and assert non-empty output remains unchanged. Leave filter-specific no-match messages, custom or intentionally different messages, and test-only baselines untouched.
- In this repository, format changed Go files and run the focused TUI package tests (for example, `go test ./internal/terminal -count=1`) before the repository validation `go build ./...`, `go vet ./...`, and `go test ./...`.
