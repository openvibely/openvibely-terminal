# Worker Capacity Table Rendering

Use this reference when implementing or auditing `/workers show`, its compatibility aliases, or another TUI command that renders independent worker-capacity sections.

- Normalize `/works show` to the existing `/workers show` command path when compatibility requires the alias; keep help, selector, plain, interactive, and CLI behavior on the same dispatch path rather than maintaining a second renderer.
- Consume structured capacity records at the client/dispatch boundary. Do not flatten a backend HTML page or opaque transcript into rows: a flattened page loses canonical columns, ordering, empty-state semantics, partial failures, and a stable JSON model.
- Keep the primary global capacity section authoritative. A global fetch failure is a command error; independent project or model section failures must preserve the usable global table and render concise warnings rather than replacing the result with a generic failure.
- Track availability separately from collection contents for every optional section. A failed project/model fetch must not be converted only into an empty slice, because an empty-state message such as `no dedicated model worker pools` would falsely claim a successful empty result. Preserve an explicit unavailable/error flag and render an unavailable state plus the warning; reserve empty-state copy for a successful empty response. In JSON, retain stable empty collections with warnings so consumers can distinguish the partial result.
- Treat `/workers show` and `/works show` as global read-only inspection. They may fetch global, per-project, and per-model capacity endpoints without a selected project, so do not apply a project guard or multi-project CLI preflight to the show action. Only `/workers project <n>` requires an active project; `/workers limit <n>` is global and also works without one. Add no-project TUI and CLI regressions that assert the show table still renders and the capacity requests occur.
- Match the web presentation with two focused tables: worker/project capacity columns are `SCOPE`, `NAME`, `RUNNING`, `QUEUE`, `LIMIT`, and `STATUS`; the model-capacity table uses `MODEL`, `RUNNING`, `LIMIT`, and `STATUS`. Put the global row first, then preserve backend project order and model order; do not sort or add unrelated capacity internals in the TUI.
- Give an empty secondary section an explicit, useful state such as an empty model-pool message. Keep partial/error states visible in plain and interactive output, while JSON uses stable `workers`, `models`, and `warnings` collections and omits fields not part of the command contract.
- Bound untrusted names and status/error cells for terminal width using the repository’s safe display-width truncation helper. Add long-value coverage that verifies output remains readable and bounded without corrupting Unicode or table structure.
- Add focused dispatch/rendering tests for exact headers, global-first ordering, rows, empty sections, long values, primary-versus-secondary errors, no-project show behavior, alias routing, concurrent independent reads, and JSON key casing/collection shape. Then run the focused package tests and the normal build, vet, full tests, race coverage for the changed path, formatting, and `git diff --check`.
- If the full race suite reports a known failure outside the worker path, isolate and report it with the exact test/location while retaining targeted race evidence for the changed path; do not mislabel the worker implementation as race-clean for the entire repository.
