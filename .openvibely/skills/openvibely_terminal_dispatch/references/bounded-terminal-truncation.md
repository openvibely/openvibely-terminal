# Bounded Terminal Truncation

Use this checklist when changing `internal/terminal/model.go` text truncation or any renderer that previews untrusted event, task, description, or lifecycle payloads.

- Preserve the established output contract: normalize newlines as spaces, measure terminal display cells rather than bytes, ignore ANSI escape width, keep grapheme clusters and wide/combining Unicode intact, handle malformed UTF-8 without emitting invalid output, trim trailing spaces before an ellipsis, and return an empty string for `n <= 0`.
- A bounded implementation must remain bounded for newline-bearing inputs as well as plain ASCII. Do not call `strings.ReplaceAll` across the entire payload or restart a complete scan after discovering a newline; that turns a large over-limit preview back into input-sized CPU and allocation work.
- Keep whole-input normalization out of the over-limit path. It is safe to normalize the complete input only after a width check has proved that the complete normalized result fits and must be returned; once the limit is exceeded, substitute newline bytes as logical spaces only while scanning/copying the retained prefix.
- Prefer a single stateful scan that stops once the output budget is decided and emits only the retained prefix. Treat a newline as its one-cell space equivalent during scanning, while preserving any grapheme-boundary rules needed by the legacy output. If exact normalization requires a fallback, prove that fallback is limited to the retained region rather than the full payload.
- For JSON-like lifecycle previews, do not repeatedly measure the growing whole buffer. Track cheap width evidence incrementally and impose a fixed retained-byte ceiling as well as a display-cell limit; combining or zero-width Unicode can consume unbounded bytes without advancing terminal width.
- Preserve `encoding/json` compatibility beyond decoded `map[string]any` and `[]any` values. Regression fixtures should include named scalars/maps, typed slices, structs, `[]byte`, nil containers, `json.Marshaler`, and `encoding.TextMarshaler` values, comparing preview output with `truncate(string(json.Marshal(value)), limit)` whenever the complete encoding fits.
- Stopping prefix generation must not skip payload validity. If the historical contract returns `<unavailable>` whenever `json.Marshal` would fail, validate the complete payload separately from bounded prefix generation so a later channel/function, non-finite float, invalid `json.Number`, cycle, or marshaler error still wins after an earlier value fills the preview. Keep validation cheap for oversized scalar strings and bounded for pathological nesting.
- Compare optimized output with a small legacy reference across ANSI, newline, malformed-byte, wide-character, combining-mark, whitespace, exact-width, and non-positive-limit cases. Include large benchmark fixtures containing early and late newlines, at multiple sizes such as 64 KiB and 1 MiB; newline-free fixtures alone cannot demonstrate bounded behavior.
- Lifecycle preview benchmarks should include ASCII and zero-width/combining scalar fixtures at multiple payload sizes and event counts. Require time and allocation results to plateau by payload size for each fixture; otherwise a byte-retention or repeated-width-scan bug can hide behind ordinary ASCII measurements.
- Benchmark both the legacy/baseline and bounded implementations with `-benchmem`, and verify that the newline-bearing bounded result stays near the retained-prefix allocation rather than scaling with payload size. Then run `go build ./...`, `go vet ./...`, and `go test ./...` from the active worktree. Truncation/rendering changes do not require the race detector unless concurrent model state also changes; in that case run the narrowest relevant package or tests under `-race`.
- Audit every `truncate` call site that can receive backend or lifecycle data, and verify that the rendered result stays within its cell budget without mutating decoded payloads. Preserve focused coverage for the affected renderer and concurrent model or event behavior.
