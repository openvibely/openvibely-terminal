# Project Scope In Destructive Agent Commands

For interactive or forced headless deletion of a project-owned agent, capture the resolved agent ID and selected project ID before entering confirmation or launching the mutation. Pass both captured values to the client; do not re-resolve through a session-default scope. Preserve protected-agent checks, ambiguity/stale-result handling, interactive yes/no confirmation, cancellation, and the CLI `--force` gate. Add two-project regressions that assert no `DELETE` occurs before confirmation or after cancellation, while confirmed interactive and forced CLI paths include the selected project's exact `project_id`; reject a valid agent when the request is scoped to a foreign project. Keep agent listing and post-delete refresh scoped to the same selected project.
