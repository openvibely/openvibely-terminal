# OpenVibely Terminal

Go terminal client built with Bubble Tea, Bubbles, and Lipgloss. It is separate from the Echo backend, which normally serves on port `3001`.

## Working Constraints

- Treat the backend repository as read-only unless explicitly authorized. Use its web UI and Swagger as parity sources for terminal behavior and naming.
- Work in the intended `.worktrees/<task-id>/` checkout. Scoped file tools are rooted at the main checkout and can affect the wrong tree; reconcile `pwd`, `HEAD`, and module/workspace before editing. Leave `main` unchanged and use fast-forward-only integration unless authorized otherwise.
- Several completed features were reported only on task branches; do not assume they are present on `main` without checking the target worktree and `HEAD`.
- The primary UI is a chat window, not a navigation shell. Chat and slash commands share one input, and command results render in the conversation. Repository build/CI commands are separate from the user-command surface.
- Destructive interactive actions require `⚠ Type 'yes' to confirm or Esc to cancel`; headless actions require `--force`/`-f`.
- Live backend integration is opt-in. Runtime checks use a fresh build so stale binaries cannot mask source changes.
- Validate Go changes with focused tests, formatting, build, vet, the ordinary full test suite, and diff checks. Use targeted race tests only for concurrency-sensitive changes or explicit acceptance criteria; parser, rendering, documentation, benchmarks, and ordinary synchronous client changes do not make all-package race testing a routine gate.

## Backend Contracts

- Core APIs are `/api/projects`, asynchronous chat (`POST /api/chat/message`, then `GET /api/chat/message/:id`), `/api/capacity/*`, `/api/analytics/*`, and Swagger routes registered by `cmd/server/main.go`.
- Authentication uses `AUTH_ENABLED` and cookie sessions. `POST /login` sets `ov_session`; `GET /auth/me` reports state. Unauthorized `302`/`401` responses across HTML, JSON, form, health, and SSE transports become typed auth-required failures; other transport failures retain offline guidance. Form mutations accept only `2xx` unless a route has an explicit exception.
- Many endpoints return HTMX/templ HTML, not JSON. HTML clients use the real web routes with HTMX headers and parse stable `data-*` attributes.
- `CreateProject` does not follow redirects and accepts only a non-login `3xx` to `/tasks` with a valid non-empty `project_id`; preserve the trimmed submitted name and path.
- Existing-project settings are authoritative from `GET /projects/:id/edit` and use full-form `PUT /projects/:id`. Require an exact project-specific form action and complete, non-duplicate controls before full replacement; hydrate managed GitHub paths omitted by disabled local-path fields from `/api/projects`, merge explicit edits into fetched values, reject source-incompatible options before mutation, and refresh authoritative state after save.
- Centralize optional query construction, including `project_id`; omit empty values and URL-encode non-empty values without changing public signatures.
- `/events/live` carries task, chat, and file-change events, including `chat_response_done`. Interactive `/events` owns a reconnectable model stream; headless `events on` and bare `events` own one foreground project-scoped stream. Task-scoped payloads require an exact non-empty selected-project ID, while taskless project chat may omit it.
- Shared SSE framing in `internal/client/sse.go` owns the 1 MiB scanner limit, event/data accumulation, comment suppression, blank-line dispatch, and full frame reset. Callers retain payload whitespace normalization, channel ownership, auth diagnostics, cancellation, disconnect, and clean-EOF semantics.
- HTML card normalization in `internal/client/html.go` skips empty markers, preserves first-seen order, and lets richer duplicates win. Shared continuation traversal for alerts, skills, models, agents, automations, channels/webhooks, and custom personalities preserves scope, filtering, order, and deduplication, capped at 200 pages or 10,000 cards. Tasks and schedules use distinct pagination behavior.
- `/tasks` is HTML/HTMX, not a JSON board. Cards use `data-task-*`; titles come from the card-title link. Detail uses backend tab IDs plus separate thread and changes fragments. `GetTask` loads sections concurrently, returns section-aware partial failures, and renders valid empty fragments as `(empty)`.
- Lifecycle executions use `GET /api/tasks/:id/lifecycle-executions?project_id=...` with newest-first page envelopes (`items`, `has_more`, optional `next_cursor`) and maximum page size 50. Strictly validate the envelope while supporting the explicit legacy top-level array; reject null, malformed metadata/items, non-object entries, and trailing JSON. Task-only lifecycle output preserves page metadata, and event traces are fetched only for an explicit execution reference.
- Skill create/edit uses backend-compatible JSON plus HTMX/Accept headers; edits preserve metadata and enabled state, boolean writes include scope, and delete stays form-based with its required scope query.
- Personality discovery uses scoped `/personality` HTML; custom CRUD uses JSON `/personality/custom`. Every request carries `project_id`; `PUT` upserts built-in overrides and `DELETE` preserves reset/active-selection behavior.
- There is no public project-scoped backend memory list/read/search/curation API. TUI memory inspection is read-only and limited to the selected project’s canonical `.openvibely/memories/MEMORIES.md` and indexed Markdown files.

## Runtime And State

- `cmd/openvibely-terminal/main.go` runs Bubble Tea interactively without arguments and headless CLI with arguments. Server, credentials, and project support flags/environment, including `-project` and `OPENVIBELY_PROJECT`. `--json`/`-json` emits snake_case for supported list/show commands and is ignored interactively. Global flags work before or after operands while command-local flags, `--`, quoting, unknown flags, and repeated flags retain standard behavior.
- Project-scoped headless commands preflight centrally after project loading. Multiple projects without `-project` fail before scoped requests or mutation; zero/single-project convenience, explicit name/full-ID/unique-prefix resolution, and interactive selection remain supported. Resource references resolve by unique exact ID, exact case-insensitive name, unique prefix, then unique substring; duplicate exact values are ambiguous.
- One-shot `status` starts project discovery, health/authentication, and capacity checks concurrently, applies project results before global checks for deterministic precedence, and starts alert/task counts only after exactly one selected project. Cancellation propagates through all overlapped requests.
- `setActiveProject(client.Project)` updates ID/name, clears thread state, restores the default placeholder only on ID change, and preserves thread/placeholder for same-ID selection.
- Async work uses monotonic session, project, SSE, and ordered request generations. Reject stale results and foreign-project events before rendering or mutation. Authentication errors take precedence over offline guidance, and completed-request errors are appended once unchanged.
- Chat submission is serialized by an in-flight guard and monotonic token. Plain input and `/chat` cannot overlap. Stream output resumes from UTF-8 byte offsets into one assistant entry with redraw throttling; flush accepted output before later transcript events. Exact or validated promoted execution IDs own completion. Empty or strict-prefix terminal snapshots retain longer streamed output; divergent snapshots correct it authoritatively.
- Task-thread replies reuse that stream state. While an acknowledged reply is pending, reject identity-less same-task status and mirrored chat events; exact or validated promoted execution identities remain authoritative. Identity-less orchestration replies use scoped thread refresh, and replacing/opening a task preserves the active reply unless a replacement thread loaded successfully. Leaving a thread cancels owned streams.
- Project loading is request-mode aware: startup, selection, and list-only fetch projects only; `/projects` also fetches non-fatal capacity data. Interactive login uses a masked retryable/cancelable password field, generic credential errors, cookie sessions, and never persists or displays credentials.

## Command Surface

- Supported areas: Tasks, Schedule, Alerts, Skills, Agents, Models, Workers, Channels, Personality, Pulse, Reflection, Grades, Insights, Automations, Analytics, Projects, `status`, SSE events, `setup`, `clear`, `help`, and `quit`. `/build` and `/api/autonomous/trigger` are intentionally absent because the backend has no matching contract.
- `/projects create <name> <path>` works interactively and headlessly, including pipe-delimited names/paths with spaces. Interactive creation selects the project and refreshes scoped SSE; headless creation reports the ID and follow-up command. `/projects show` and `/projects edit` follow the authoritative settings contract. Separator and literal-pipe interpretations use the same project ranking; stronger shorter matches win and equal-strength interpretations for distinct projects fail ambiguous before detail or mutation. The outer `--` supports project names shaped like global flags.
- `/tasks open <ref>` enters a project-scoped task thread; `/task open` is an intentional alias. `/chat` returns to project chat. `/tasks show <ref> <tab>` supports detail, thread/chat, changes/diff, schedule, chaining, attachment, and lifecycle aliases. Canonical lowercase 32-hex task IDs may use a direct scoped detail path only after strict task/project identity validation; unknown or foreign IDs must not expose detail or fall back to board scans. Noncanonical references and actions keep board matching. Sanitize all task review metadata while preserving multiline comment bodies.
- Help, validation, selectors, and Tab completion derive from structured command-registry metadata. Completion is depth-aware, changes only the relevant span, preserves quotes/pipes/trailing text, and does not guess on ambiguity. Interactive missing/partial refs may open a searchable picker; CLI returns usage errors and never auto-executes a partial match.
- Automation’s canonical action is `run`; `run-now` is a compatibility alias mapped to `/automations/:id/run-now`. `/automations show` is canonical and `open` is a compatibility alias. Run, pause, resume, and delete execute once against the resolved canonical ID; mutation failure yields neither success nor refresh, while refresh failure after success preserves success status.
- Attachments are project-scoped repeated multipart `files`; deletion is confirm/force gated. Upload validates all paths before requests, streams fixed-length input by lazily opening one file at a time, preserves order/duplicates, bounds descriptors, supports cancellation of blocked reads, detects replacement/size changes, and reports path-specific local failures before HTTP wrapping. Reject non-regular files; support symlinks to regular files; Unix open paths including AIX/illumos are nonblocking and descriptor-verified.
- Workers show is global read-only; worker project and limits are scoped where applicable. Limits accept nonnegative decimals and `0` means unlimited. Analytics propagates selected project to every endpoint; agent metrics are global and votes are project-scoped. Pulse, Reflection, Grades, Insights, Skills, Automations, Alerts, Channels, and project-bound Agents require project selection before parsing, prompting, or dispatch.
- Schedule reads/mutations carry `project_id`. Successful mutation remains successful if refresh fails. Edit supports `run-at`, `repeat`, `interval`, and `clear-context`; parse and validate its deterministic settings section before project loading or requests, and require quotes for titles containing setting-like text. Exact IDs outrank titles; `hourly` normalizes to backend `hours`. `/schedule show` is canonical and `open` is an identical alias; interactive omissions open a picker, headless omissions return usage. Show loads the exact bound task metadata in scope and treats only typed `404` as a missing bound task; auth, transport, server, malformed, and identity errors remain visible. Deletion resolves and captures the canonical target before confirmation or force gating, uses terminal-safe canonical labels, and cannot rebind after catalog changes.
- Models classify list/filter reads as global and capacity/default/delete as project-scoped. Filters match name, model, and provider case-insensitively. Typed and picker default/delete share canonical post-resolution mutation behavior while retaining caller-specific matching, picker, confirmation, and busy state.
- Alerts aggregate pages with stable first-page precedence. Canonical ID detail lookup can stop on the matching page but must enforce continuation limits before returning; completed misses reuse collected cards for ordinary matching. Action matching prioritizes ID and case-insensitive title tiers before searchable body text. Mutating typed references resolve and capture targets before confirmation/force gating; sanitize only displayed diagnostics, not matching inputs.
- Channels support secret-free list/show, setup/connect, edit, test where available, remove, and disconnect for GitHub, Slack, Telegram, Discord, X, and Email. Credential-clearing disconnects and destructive removal are confirmation/force gated. Validation covers conditional provider credentials and real GitHub auth-mode, Slack bot-token-mode, and Email-provider transitions; headless edits fetch and reuse authoritative state so restating a current mode does not require transition credentials. Preserve safe Slack metadata only; mask credentials and reconstruct flattened GitHub App PEM input without rendering it. Validate GitHub API HTTP(S) URLs and Email mailbox addresses before requests. Canonical inbound-webhook management is `/channels webhooks`; `/webhooks` and `/inbound-webhooks` are hidden, documented deprecated aliases using the same dispatcher. Webhook partial edits preserve secret-free details, tests show created task IDs, secrets are not rendered, and rotate/delete resolve and capture targets before confirmation/force gating.
- Agent edit supports `name`, `description`, `system-prompt`, `model`, `key`, `scope`, `enabled`, and `selectable`. Read authoritative project-scoped definition/lifecycle state, reject protected/foreign definitions, validate model as `inherit` or exact configured model before mutation, preserve advanced/lifecycle data in full updates, and sanitize displayed labels/reference diagnostics without changing raw matching. Delete also resolves/captures the target before confirmation.
- Automation detail renders bounded topology, role/type, allowlisted configuration, runtime/status, resources, external state, and explicit empty/partial/error states. Omit sensitive prompts, instructions, credentials, tokens, and secret-like fields. Render edge conditions only through a bounded allowlist. Editing uses `GET /automations/:id/builder` authoritative YAML; preview posts without `save_changes`, and persistence adds it only after successful validation. Interactive editing is a native multiline editor whose teardown cancels in-flight preview/save work; unchanged, canceled, stale, or invalid edits do not save. Headless export writes a new owner-only file without mutation; `--file` replaces the complete definition. Fail closed unless builder form action exactly matches automation and selected project; never echo YAML.
- `/memory` and `/memories` are read-only scoped list/show/search. Trust only safe handles indexed in `MEMORIES.md`; reject/warn traversal, absolute paths, index self-references, and incidental prose mentions. Collections are stable and non-nil in JSON; plain output omits repository paths and secret-bearing data.
- `setup` is a backend-independent, non-project-scoped, read-only command available interactively and headlessly. It makes no HTTP, installation, clone, process, filesystem, or machine-state changes, and gives platform-specific install/startup/status/remote-connection guidance. Render configured server URLs after removing user info, query, fragment, and terminal controls.

## Rendering And Safety

- `connectionPhase()` centralizes header, status, and input-hint connection presentation. Auth-required wins precedence; reachable backend failures use safe diagnostics without claiming connection or advising server startup. Offline/status recovery points explicit unreachable remotes to URL correction before local setup; reachable-but-unhealthy diagnoses remain distinct. Redact URLs and Authorization credentials, including Basic and Bearer, and normalize configured HTTP(S) schemes before request or rendering.
- Analytics graphs cover usage, outcomes, execution time, frequent tasks, failure patterns, and skill follow-through. Execution-time results are stable-sorted, bounded to 12, and do not mutate caller data.
- `truncate` handles bounded UTF-8/display width, ANSI, malformed bytes, wide/combining characters, whitespace, ellipsis, exact width, and nonpositive widths. Invalidate transcript/table caches on resize, clear, mismatch, history eviction, and relevant picker/filter changes.
- Zero-project onboarding waits on `projectsLoaded`; delayed startup must not show empty-account guidance prematurely. Raw and implicit-project JSON omit `error`/`system` roles, trim trailing newlines, skip empty entries, and preserve project metadata.
- Lifecycle plain previews are bounded, deterministic, canonical JSON-like output; raw `--json` remains complete. Ambiguous ordering, collisions, cycles, unsupported maps, overflow, and unknowable late errors fail closed as `<unavailable>`.
- Event command validation rejects unknown modes and surplus operands before requests/state changes. One-shot chat/task replies can stream stable NDJSON, reconnect by exact UTF-8 offset, reconcile terminal status authoritatively, explicitly report unexpected EOF/deadline/reconnect exhaustion, and keep caller cancellation quiet.
- Memory output strips terminal controls and bounds lines/documents. Reads prevent directory/symlink escape, revalidate regular-file identity, use nonblocking no-follow handling, and cap documents at 8 MiB. Search parses each bounded indexed document once into original and normalized forms.
- CI keeps vet and coverage independent, uses bounded timeouts and non-empty profiles, awaits status propagation, gates summaries on success, and uses uncached tests for manual/reusable runs while ordinary push/PR coverage may use successful-test cache.

## Active Findings

- Interactive `/pulse`, `/reflection`, `/grades`, and `/insights` accept unknown actions or surplus operands. Invalid forms should fail before requests without changing valid behavior.
- Malformed server URLs, such as invalid percent escapes in `-server`, are mislabeled as a responding unhealthy backend; classify them as invalid server configuration with URL-correction guidance.
- The backend supports model-connection create/edit, but the TUI currently exposes only list, default, delete, and capacity.
- Release and installation support remains limited to the Unix-oriented local `make build` route and Ubuntu-only CI. There are no release artifacts, release workflow, or discoverable platform-specific installation path.
- Broader transcript redraw/caching and unnecessary full-detail fan-out for explicit task tabs are already tracked; do not duplicate those issues.
- Canonical full-ID `tasks show` output cannot match board `display_order` or the ordinary child `Chained` badge without a backend contract exposing stored order and `ParentTaskID`, a board request, or explicit requirement relaxation. Preserve direct-detail identity validation and do not silently invent missing metadata.
- Canonical full-ID automation lookup still traverses the complete paginated catalog before detail, so latency and transfer scale with catalog size. Any optimization needs direct-detail behavior with a draft-`404` metadata fallback and measured 10/100/1,000-item latency, byte, and allocation evidence.
- Project selection/creation offers minimal state-aware next actions; users may not discover pending approvals, active work, upcoming schedules, or empty projects without invoking status-oriented commands.
- Guided and headless channel setup/edit duplicate the post-save refresh/status/table tail; share only that completion path while retaining distinct preparation and secret-handling paths.
- Memory search rescans full indexed documents and may scale poorly with a large corpus. No current user-visible slowdown is established; benchmark realistic corpus sizes and preserve output before optimizing.
