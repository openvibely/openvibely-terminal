# OpenVibely Terminal

Go terminal client built with Bubble Tea, Bubbles, and Lipgloss. It is separate from the Echo backend, normally served on port `3001`.

## Working Constraints

- Treat the backend repository as read-only unless explicitly authorized; use its web UI and Swagger as behavior and naming parity sources.
- Work in the intended `.worktrees/<task-id>/` checkout. Scoped memory tools point at the main checkout, so verify `pwd`, `HEAD`, and module/workspace before edits. Keep shared `main` unchanged; integrate by fast-forward and rebase task branches onto the current target rather than merging on `main`.
- Features reported on task branches are not necessarily in `main`; verify the target worktree and `HEAD` before relying on them.
- The primary UI is a chat window. Chat and slash commands share one input and command results render in the conversation; build and CI commands are not user commands.
- Destructive interactive actions require `⚠ Type 'yes' to confirm or Esc to cancel`; headless destructive actions require `--force`/`-f`.
- Live backend integration is opt-in. Runtime checks require a fresh build so stale binaries cannot hide source changes.
- Validate Go changes with focused tests, formatting, build, vet, ordinary full tests, and diff checks. Use targeted race tests for concurrency-sensitive work or explicit acceptance criteria. Exact-`HEAD` evidence belongs in durable Git notes.
- The module declares Go `1.27.1`; GitHub Actions uses `go-version-file: go.mod`. There is no `toolchain` directive or alternate Go-version configuration.
- Release/install support is Unix-oriented through local `make build` and Ubuntu-only CI; there are no release artifacts, release workflow, or discoverable platform-specific installation paths.

## Backend And Client Contracts

- Core APIs include `/api/projects`, async chat (`POST /api/chat/message`, then `GET /api/chat/message/:id`), `/api/capacity/*`, `/api/analytics/*`, and Swagger routes registered by `cmd/server/main.go`.
- Authentication uses `AUTH_ENABLED` and cookie sessions (`POST /login`, `ov_session`, `GET /auth/me`). Unauthorized `302`/`401` responses across HTML, JSON, form, health, and SSE are typed auth-required failures; other transport failures retain offline guidance. Form mutations accept only `2xx` unless documented otherwise.
- Many backend endpoints are HTML/HTMX rather than JSON. Use real web routes with HTMX headers and parse stable `data-*` attributes.
- Project creation accepts only a non-login redirect to `/tasks` with a valid non-empty `project_id`; preserve trimmed submitted name and path. Existing settings come authoritatively from `GET /projects/:id/edit` and are saved as a complete `PUT /projects/:id` form. Hydrate managed GitHub paths from `/api/projects` when disabled local-path fields omit them.
- Optional query construction omits empty values and URL-encodes non-empty values without changing public signatures.
- `/events/live` carries task, chat, and file-change events. Interactive `/events` owns a reconnectable model stream; headless `events on` and bare `events` own one foreground project-scoped stream. Task-scoped events require an exact non-empty selected project ID; taskless project chat may omit it. Shared SSE framing handles a 1 MiB scanner limit, multiline event/data accumulation, comment suppression, blank-line dispatch, and frame reset.
- `/tasks` is HTML/HTMX, not a JSON board. `GetTask` loads backend tabs plus separate thread/changes fragments concurrently, preserves section-aware partial failures, and renders valid empty fragments as `(empty)`. Canonical lowercase 32-hex task IDs use direct scoped detail only after strict task/project identity validation; unknown or foreign IDs do not expose detail or fall back to board scans.
- Lifecycle executions use paginated `GET /api/tasks/:id/lifecycle-executions?project_id=...`, newest first, maximum page size 50. Validate page envelopes strictly while supporting only the explicit legacy top-level array, and fetch event traces only for an explicit execution reference.
- Shared HTML-card continuation traversal preserves scope, filtering, first-seen order, richer duplicates, and deduplication, capped at 200 pages or 10,000 cards. Tasks and schedules have distinct pagination behavior.
- Skill edits use backend-compatible JSON plus HTMX/Accept headers; preserve metadata and enabled state, include scope for boolean writes, and retain form-based scoped delete. Full-content JSON skill lists enrich every skill with bounded, order-preserving detail fetching: catalogs of 10 or fewer remain serial to protect the zero-delay allocation budget, while larger exports use a fixed eight-worker pool with cancellation and ordered error propagation. Plain interactive skill listing remains metadata-only. Canonical project-skill detail may fall back to summary resolution only for typed `404`/`503` unavailable project-skill roots; other errors are terminal.
- Personalities use scoped `/personality` HTML and `/personality/custom` JSON; every request carries `project_id`. Model connections use backend-owned `POST /models`; API-key and OAuth behavior must be backend-confirmed.
- No public backend memory API exists. Terminal memory inspection is read-only and limited to the selected project's canonical `.openvibely/memories/MEMORIES.md` and indexed Markdown files.

## Runtime And Interaction

- `cmd/openvibely-terminal/main.go` uses Bubble Tea without arguments and headless CLI with arguments. Server, credentials, and project support flags/environment, including `-project` and `OPENVIBELY_PROJECT`. `--json` emits snake_case for supported list/show commands and is ignored interactively.
- Project-scoped headless commands preflight after project loading. Multiple projects without `-project` fail before scoped requests or mutation; zero/single-project convenience, explicit name/full-ID/unique-prefix resolution, and interactive selection remain supported. References resolve exact ID, case-insensitive exact name, unique prefix, then unique substring; duplicate exact values are ambiguous.
- Async work uses monotonic session, project, SSE, and ordered-request generations. Reject stale results and foreign-project events before rendering or mutation. Auth errors outrank offline guidance; append completed-request errors only once.
- Chat submission is serialized and tokenized. Stream UTF-8 byte-offset output into one assistant entry with redraw throttling, flush it before later transcript events, and let valid promoted execution IDs own completion. Terminal snapshots may correct divergent stream output authoritatively. Task-thread replies retain equivalent ownership and cancellation protections.
- `setActiveProject` clears thread state and resets the default placeholder only on project ID changes. Project loading is request-mode aware; interactive login is masked, retryable/cancelable, and never persists or renders credentials.
- Help, validation, selectors, and Tab completion derive from structured command-registry metadata. Completion is depth-aware, quote/pipe-safe, and does not guess on ambiguity. Interactive partial references may offer a picker; CLI returns usage errors and never auto-executes partial matches.
- Canceled headless task commands preserve the caller-owned `RunCLIContext` through project loading and dispatch. Task list/lookup/lifecycle/attachment/open/mutation paths honor it, and mutation remains guarded after reference resolution.
- Zero-project onboarding waits for `projectsLoaded`. `setup` is backend-independent, non-project-scoped, and read-only: it makes no HTTP, installation, clone, process, filesystem, or machine-state changes.

## Command And Data Rules

- Supported areas include Tasks, Schedule, Alerts, Skills, Agents, Models, Workers, Channels, Personality, Pulse, Reflection, Grades, Insights, Automations, Analytics, Projects, `status`, events, `setup`, `clear`, `help`, and `quit`. `/build` and `/api/autonomous/trigger` are intentionally absent because no backend contract exists.
- `/projects create`, `show`, and `edit` follow the project contracts above. Local `projects create <name> <path>` remains purely local. Backend-managed GitHub creation is the distinct `projects github-create <name> <url>` action, available even when local repository paths are disabled; it sends `repo_source=github` and `repo_url` while omitting `repo_path`.
- `/tasks open` enters a project-scoped thread, `/task open` is an alias, and `/chat` returns to project chat. Task review metadata is sanitized while multiline comment bodies remain intact.
- Automations use canonical `run` and `show`; `run-now` and `open` are compatibility aliases. Resolve typed references through one project-scoped catalog request before mutation. Builder editing uses authoritative YAML from `GET /automations/:id/builder`; preview never saves, persistence adds `save_changes` only after successful validation, and YAML is never echoed. Details render only bounded allowlisted topology/configuration/status fields and omit prompts, instructions, credentials, tokens, and secret-like fields.
- Attachments are project-scoped multipart `files`; deletion is confirmation/force gated. Upload validates all paths before requests, streams files lazily with bounded descriptors, supports cancellation, detects replacement/size changes, rejects non-regular files, and permits symlinks only to regular files. Streaming is materially lower-memory and earlier-delivering than buffering; no further upload-buffering optimization is open.
- Project-bound Pulse, Reflection, Grades, Insights, Skills, Automations, Alerts, Channels, Agents, and Analytics require project selection before parsing, prompting, or dispatch. Their documented bare/read/trigger syntax rejects unknown actions and surplus operands locally before requests.
- Schedule requests carry `project_id`; successful mutations remain successful if refresh fails. Direct and picker-based schedule toggles share one smallest command-local post-resolution helper for the scoped toggle request and refresh/status tail; lookup/reference resolution, picker construction, cancellation, and delete confirmation remain distinct. Parse deterministic edit settings before project loading, retain authoritative `ClearContextOnStart` unless explicitly changed, and capture canonical deletion targets before confirmation. Exact IDs outrank titles. Repeat selects use the first option when no option is marked selected, and malformed required fields fail before `PUT`.
- Models treat list/filter as global and capacity/default/delete as project-scoped. Default/delete mutations carry the selected `project_id` and reject missing scope locally. API keys are accepted only through masked interactive input or redirected/piped `--api-key-stdin`, never command arguments. Redact secrets from rendering, errors, history, logs, and JSON, including malformed sensitive input; malformed sensitive sequences fail closed before requests. Reject embedded endpoint credentials, query, and fragments. Full-form model edits retain authoritative fields and private credentials; API-key-compatible edits use the backend preservation marker.
- Alert pagination preserves first-page precedence. Explicit `--decision-state` and optional `--processing-state` predicates carry `project_id` on all pages; free-text terms stay independent local matching. Plain and JSON list output use the same title/searchable-text/message/ID predicate, preserve workflow predicates and ordering, and serialize filtered no-match results as a non-nil `[]`. Bulk read/delete resolve all scoped targets before mutation, require valid non-negative response counts, and capture interactive deletion targets before confirmation.
- Channels support credential-safe list/show/setup/edit/test/remove/disconnect for GitHub, Slack, Telegram, Discord, X, and Email. Webhooks are canonically under `/channels webhooks`; older paths are hidden deprecated aliases. Canonical webhook IDs use scoped direct detail and require exact selected-project identity; only typed detail `404` may fall back to catalog matching.
- The backend also exposes saved outbound message destinations with add, edit, delete, test, per-platform Home selection, and an explicit-unsaved-target policy, but the terminal currently has no target model, route, command, rendering, or help surface for this workflow.
- Channel access rows require explicit selected-project ownership evidence and fail closed when missing, malformed, conflicting, or foreign. X rows additionally require persisted authorized-user/project and user markers directly on every row. Email identities come only from a validated canonical sender field; Telegram identity comes only from canonical template spans. Destructive removal resolves captured row IDs or canonical identity aliases, never arbitrary display-name metadata.
- Agent edits read authoritative scoped definition/lifecycle state, reject protected or foreign definitions, validate model choices, preserve advanced/lifecycle fields, and capture deletion targets before confirmation. Project deletion captures the canonical ID, uses exact ID/name then unique prefix/substring resolution, requires `yes`/Esc or `--force`, sanitizes terminal errors, treats malformed redirect hints as advisory, and refreshes selection after success.
- Active task steering is project-scoped and guarded by the exact active execution turn. Missing execution identity, stale turns, or ambiguous active turns fail closed before POST or normal-reply fallback. Delayed results are rejected by project/thread/generation identity; plain acknowledgements and errors are terminal-safe while JSON identity fields remain stable.
- Task goals support project-scoped set, clear, pause, and resume. `tasks goal pause <task>` and `resume <task>` are control actions; `tasks goal <task> | pause` remains ordinary set-goal objective syntax.

## Reliability And Security

- `connectionPhase()` centralizes connection header/status/input hints. Auth-required takes precedence; reachable backend failures use safe diagnostics without claiming connection or advising server startup. Explicitly unreachable remotes direct URL correction before local setup. Redact URL user info and Authorization credentials; normalize configured HTTP(S) schemes before requests or display.
- Malformed configured server URLs, including invalid percent escapes and malformed authorities, are rejected before any request as typed invalid configuration. Interactive status, one-shot status, configured login, and read-only setup direct users to correct `-server` or `OPENVIBELY_SERVER_URL`; they do not claim connectivity or suggest local startup.
- Rendering helpers safely handle UTF-8/display width, ANSI, malformed bytes, wide/combining characters, whitespace, ellipsis, and nonpositive widths. Invalidate transcript/table caches after resize, clear, mismatches, history eviction, and relevant picker/filter changes.
- Lifecycle plain previews are bounded, deterministic, and fail closed as `<unavailable>` on uncertain ordering, collisions, cycles, unsupported maps, overflow, or unknowable late errors; raw JSON remains complete.
- One-shot chat/task replies may stream stable NDJSON and reconnect by exact UTF-8 offset. Reconcile terminal status authoritatively; report unexpected EOF, deadline, or reconnect exhaustion, while caller cancellation remains quiet.
- `events --json` preserves raw `data` for every syntactically valid JSON value, including arrays, strings, numbers, `null`, and known-field type mismatches; malformed JSON omits `data`. A taskless chat event with an empty or missing server `project_id` is rewritten to the selected project ID, while non-empty scoped task events still require exact filtering. The large-payload byte-oriented fast path is complete and must retain these semantics, fallback behavior, ordering, and cancellation.
- JSON output omits `error`/`system` roles, trims trailing newlines, skips empty entries, and preserves project metadata.
- CI keeps vet and coverage independent, with bounded timeouts, non-empty profiles, awaited status propagation, success-gated summaries, and uncached tests for manual/reusable runs. A bounded Ubuntu 24.04/Go `1.27.1` benchmark on the exact checkout collected 60 valid matched samples across `GOMAXPROCS=1`, `2`, and runner-default candidates in routine and uncached modes; `GOMAXPROCS=2` was slower in both modes, while runner-default failed the uncached p95 and routine peak-RSS safeguards, so the cap remains `1`. The local workflow harness renders simulated inputs for both cache modes while retaining overlap, independent-failure, reaping, and coverage checks. The benchmark environment was a Linux container rather than an actual hosted `ubuntu-latest` runner.

## Established Current State

- The project-selection and channel-access backend contract is integrated upstream, but deployment status is unknown. Continue to fail closed when a backend lacks the project-scoped authorization contract. Model-provider editing and webhook-detail identity validation exist on task worktrees; verify their integration rather than assuming they are in `main`.
- Model add/edit share one post-save result policy for refresh, output, OAuth status/auth handoff, and errors while retaining action-specific ID resolution. Alert filtering, schedule form parsing and toggle handling, GitHub actor management, project deletion, task steering, live-event identity checks, selector filtering, and large-event JSON formatting have completed fixes and regression coverage; do not preserve their old intermediate failure narratives.
- Project settings distinguish inherited worker limit (`nil`) from explicit unlimited (`0`, rendered `No limit`) and positive limits. Global status renders `max_workers: 0` as `Unlimited` and omits the sentinel free-slot value, while finite global limits retain maximum and free counts; `/workers` and `/status` use consistent unlimited terminology. Backend count semantics retain hidden-category, swarm-child, project-isolation, ordinary-scheduled exclusions, and capacity-queued scheduled work when unfinished dispatch and durable reservation have no execution.
- Pulse, Reflection, Grades, and Insights share a narrow lifecycle dispatcher for project validation, strict parsing, timeout dispatch, and trigger-before-fetch short-circuiting while retaining command-specific metadata and rendering. Alerts, skills, models, agents, personalities, and automations share generic first-seen cross-page aggregation; resource-specific parsing, richer-card selection, filtering, identity keys, ordering, and alert early-match behavior remain local.
- Validation and audit history is intentionally kept in Git notes and task systems rather than this memory. This file records the resulting behavior and decisions, not commit-by-commit transcripts, benchmark samples, or completed task summaries.

## Open Findings

- Analytics parity is incomplete: the backend and web dashboard expose `GET /api/analytics/execution-trends-by-hour`, but terminal registry, client, renderer, help, tests, and documentation do not.
- Canonical full-ID automation lookup still traverses the full paginated catalog before detail. A direct-detail path needs typed-`404` metadata fallback and before/after latency, byte, and allocation evidence.
- Direct canonical full-ID task detail cannot reproduce board `display_order` or ordinary child `Chained` status without stored order/`ParentTaskID`, a board request, or an explicit requirement change; do not invent missing metadata.
- Project selection/creation offers limited state-aware next actions, so users may not discover pending approvals, active work, upcoming schedules, or empty projects without status-oriented commands.
- Project picker rows are constructed inline by the multi-project `/project` flow and separately by the shared `projectSelector` flow used by `/projects show`, `/projects edit`, and `/projects delete`, duplicating the same display-row responsibility. Notification `d7e36e4646d80d13e13cfc7825e58b36` records the narrow consolidation candidate and is pending review; preserve command-specific selection behavior while centralizing row construction.
- The read-only memory workflow repeats its JSON presentation/error tail across `list`, `show`, and `search` even though fetch/filter logic and plain renderers are intentionally distinct. Notification `0286662bffdbd5523930edaf042b5dde` records the smallest safe consolidation and is pending review.
- CI concurrency tuning was evaluated with matched routine/uncached wall-time, CPU, and peak-memory measurements; the bounded candidates did not meet the adoption thresholds, so `.github/workflows/test.yml` remains capped at `GOMAXPROCS=1`.
- Full-content skill export concurrency is implemented with serial loading for small catalogs and a bounded eight-worker pool for larger catalogs, with cancellation, ordered error propagation, exact-HEAD validation evidence, corrected response-byte accounting, practical repeated benchmark samples, and concurrent-path regressions recorded in the task's Git notes.
- The CI workflow’s background `go vet` path has no explicit signal/timeout cleanup, and `.github/workflows/test_workflow.sh` covers normal completion and failure reaping but not cancellation or timeout scenarios; the required no-orphan-process behavior remains unverified.
- Outbound message-target parity is incomplete: the backend/web settings support saved destination lifecycle management, testing, Home-target selection, and unsaved-target policy, while the terminal exposes no corresponding workflow. Product suggestion `c2e337b61c0a0adf82d1cd0e7df2755a` is pending human review.
- Task-list filter parity is broken in JSON mode: documented `tasks [filter]` filtering is applied by the human board against title, ID, and prompt, but JSON serializes the full fetched list, so a filtered JSON request can return unrelated tasks. Bug suggestion `316f5b2393b52af4836a80f0545b2a56` is pending review; add filtered-match and filtered-no-match JSON regressions matching human semantics.
- Lifecycle activity-log preview formatting has a scale-dependent performance risk for large structured payloads: repeated measurements show work and allocations grow sharply with event count and payload size even though displayed output is bounded to 512 bytes. Performance notification `fb0af495e742a1c945647f6cf7ce7126` is pending review; any optimization must preserve canonical ordering, error detection, bounded preview semantics, raw JSON completeness, and cancellation behavior, with before/after latency and allocation evidence.
