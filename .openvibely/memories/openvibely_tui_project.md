# OpenVibely TUI

Go terminal UI built with Bubble Tea, Bubbles, and Lipgloss. It is a separate client from the Echo backend, which normally serves on port `3001`.

## Durable Constraints And Workflow

- Treat the backend repository as read-only unless the user explicitly authorizes changes. Use the web UI and Swagger as parity sources for terminal behavior and naming.
- Work and validate in `.worktrees/<task-id>/` or explicitly select the intended worktree before editing. Scoped tools are rooted at the main checkout and can silently touch the wrong checkout; reconcile `pwd`, `HEAD`, and module/workspace selection when results contradict source. Task branches are rebased onto `main`; leave `main` unchanged and integrate fast-forward-only unless authorized otherwise.
- The primary UI is a chat window, not a navigation shell. Chat and slash commands share one input, and command results render in the conversation. Repository build/CI commands remain separate from the user-command surface.
- Destructive interactive actions require `⚠ Type 'yes' to confirm or Esc to cancel`; headless actions require `--force`/`-f`.
- Live backend integration is opt-in, and runtime checks use a fresh build so stale binaries cannot mask source changes.
- Go validation defaults to focused tests plus formatting, build, vet, the ordinary full test suite, and diff checks. The race detector is targeted and evidence-driven: run the narrowest relevant package or tests when a change affects goroutines, synchronization, shared mutable state, concurrent cancellation, or when acceptance criteria explicitly require it. Parser-only, rendering, documentation, benchmark, and ordinary synchronous client changes do not justify `go test -race ./...` as a routine completion gate. Historical task notes that mention race tests are evidence about those revisions, not standing instructions for later work.

## Backend Contracts

- Core contracts include `/api/projects`, asynchronous chat (`POST /api/chat/message`, then `GET /api/chat/message/:id`), `/api/capacity/*`, `/api/analytics/*`, and Swagger routes registered by `cmd/server/main.go`.
- Authentication is controlled by `AUTH_ENABLED` and cookie sessions. `POST /login` sets `ov_session`; `GET /auth/me` reports state. Unauthorized `302`/`401` responses across HTML, JSON, form, health, and SSE transports become typed auth-required failures; other transport failures retain offline guidance. Form mutations accept only `2xx` by default.
- Many endpoints return HTMX/templ HTML rather than JSON. HTML clients use real web routes with HTMX headers and parse stable `data-*` attributes.
- `CreateProject` is the redirect exception: it does not follow redirects and accepts only a non-login `3xx` to `/tasks` containing a valid non-empty `project_id`. The submitted trimmed name/path is retained.
- Existing-project settings use authoritative `GET /projects/:id/edit` HTML plus full-form `PUT /projects/:id` submission for name, description, repository source, local repository path or GitHub URL, default agent, and maximum workers. Before a full-replacement update, the client requires an exact project-specific form action and complete, non-duplicate controls; managed GitHub paths omitted from disabled-local-path forms are hydrated from `/api/projects`. Explicit edits are merged into the fetched form so omitted values survive, source-incompatible path/URL options are rejected before mutation, backend validation/environment/clone failures remain visible with terminal-safe diagnostics, and authoritative state is refreshed after saving.
- Optional query construction, including `project_id`, is centralized through the client query helper. Empty values are omitted and non-empty values are URL encoded without changing public method signatures.
- `/events/live` carries task, chat, and file-change events, including `chat_response_done`. Interactive `/events` manages a reconnectable model-owned stream; headless `events on` and bare `events` own one foreground project-scoped stream. Task-scoped payloads require an exact non-empty selected-project ID; taskless project-chat payloads permit omitted project identity.
- SSE framing is shared through one private raw helper in `internal/client/sse.go`. It owns the 1 MiB scanner limit, raw event/data accumulation, comment suppression, blank-line dispatch, and complete frame reset; callers retain their distinct payload whitespace normalization, transport/channel ownership, auth diagnostics, cancellation, disconnect, and clean-EOF contracts.
- HTML card normalization lives in `internal/client/html.go`: empty markers are skipped, first-seen order is stable, and richer duplicate data wins. Shared continuation traversal for alerts, skills, models, agents, automations, channels/webhooks, and custom personalities preserves scope, filters, order, and deduplication; it is capped at 200 pages or 10,000 cards. Tasks and schedules do not use this shared pagination contract.
- `/tasks` is HTML/HTMX, not a JSON board. Cards use `data-task-*`; titles come from the card-title task link. Detail uses backend tab IDs plus separate thread and changes fragments. `GetTask` loads sections concurrently, returns section-aware partial failures, and renders valid empty fragments as `(empty)`.
- `GET /api/tasks/:id/lifecycle-executions?project_id=...` authoritatively returns a page envelope shaped as `{"items":[...],"has_more":bool,"next_cursor":string?}`, newest first, with a maximum page size of 50. The TUI lifecycle client strictly validates this envelope and preserves an explicitly supported legacy top-level array shape; it rejects `null`, malformed metadata/items, non-object execution entries, and trailing JSON rather than permissively flattening schema errors. On branch `task/54c798bd-decode-and-display-ta[REDACTED]`, lifecycle output adds explicit empty state, continuation metadata, bounded terminal-safe previews, and complete validated page-envelope `--json` output. Task-only lifecycle requests render or serialize that page for zero, one, or multiple executions, preserving `has_more`, `next_cursor`, and forward-compatible metadata; event traces are fetched only when an execution reference is explicit. Multi-item interactive requests retain the execution selector.
- Skill create/edit uses backend-compatible JSON and HTMX/Accept headers. Edit preserves metadata and enabled state while replacing the body; enabled/always-use writes include the boolean and scope. Delete remains form-based with the required scope query.
- Personality discovery uses scoped `/personality` HTML; custom CRUD uses JSON `/personality/custom` routes. `PUT` upserts built-in overrides, `DELETE` preserves reset and active-selection semantics, and every request carries `project_id`.
- The backend has no public project-scoped memory list/read/search or curation API. TUI memory inspection is read-only and uses only the selected project's canonical `.openvibely/memories/MEMORIES.md` and indexed Markdown files.

## Runtime And State

- `cmd/tui/main.go` runs interactive Bubble Tea with no arguments and headless CLI with arguments. Server, credentials, and project are configurable by flags/environment, including `-project` and `OPENVIBELY_PROJECT`. `--json`/`-json` emits snake_case output for list/show commands and is ignored interactively. Global flags can appear before or after operands; command-local flags, `--`, quoting, unknown flags, and repeated flags retain standard behavior.
- Project-scoped headless commands perform central preflight after project loading. Multiple projects without `-project` fail before project-scoped requests or mutation with actionable guidance. Zero/single-project convenience, explicit name/full-ID/unique-prefix resolution, and interactive selection remain supported. Resource references resolve by unique exact ID, exact case-insensitive name, unique prefix, then unique substring; duplicate exact values remain ambiguous.
- One-shot `status` starts project discovery, health/authentication, and capacity checks as one concurrent global wave, then applies project results before global-check results to preserve deterministic state and error precedence. Alert/task counts start concurrently only after exactly one project is selected; zero or multiple projects and project-list failures make no scoped count requests. CLI cancellation propagates through the overlapped requests.
- `setActiveProject(client.Project)` is the shared project transition. It updates ID/name, clears thread state, restores the default placeholder only when the ID changes, and preserves thread/placeholder for same-ID selection.
- Async state uses monotonic `sessionGeneration`, `projectGeneration`, and `sseGeneration`. Stale results and foreign-project events are rejected before display or mutation. Task opens, refreshes, and replies also use ordered request IDs so delayed responses cannot regress newer state.
- Authentication errors take precedence over offline/transport guidance; ordinary completed-request errors are appended once unchanged. Project creation, attachment target resolution, and task-thread opening share this policy while retaining handler-specific stale guards and success behavior.
- Chat submission is serialized with a monotonic token and in-flight guard. Overlapping plain input and `/chat` are rejected visibly. Pending completion settles only for an exact execution ID or validated promoted ID. Per-execution output resumes at UTF-8 byte offsets, accumulates into one assistant transcript entry, and throttles redraws to a 33 ms cadence. Accepted buffered output must flush before later transcript entries, auth/login/project transitions, overlap warnings, and matching completion events. Terminal completion preserves already streamed output when the status response is empty or a strict prefix, while divergent terminal responses remain authoritative corrections. Render generations prevent stale ticks from clearing replacement timers. Task-thread replies reuse this stream state machine when the backend returns an execution or queue identity. While an acknowledged task reply is pending, identity-less same-task `task_status_changed` and mirrored `chat_new_message` events are rejected before status, transcript, or generic `/events` mutation; exact or validated promoted execution identities remain authoritative. Identity-less orchestration replies use a scoped thread-refresh fallback.
- Project loading is request-mode aware: startup, selection, and list-only paths request only projects; `/projects` also fetches non-fatal capacity data. Interactive login uses a masked retryable/cancelable password field, cookie sessions, generic credential errors, and no credential persistence/output.

## Rendering And Safety

- `connectionPhase()` centralizes header, status, and input-hint connection presentation. Auth-required has priority; reachable backend errors show safe diagnostics without claiming connection or advising the user to start the server.
- Analytics renders terminal graphs for usage, outcomes, execution time, frequent tasks, failure patterns, and skill follow-through. Execution-time results are stable-sorted, bounded to 12, and do not mutate caller data.
- `truncate` performs bounded UTF-8/display-width scanning with ANSI, malformed bytes, wide/combining characters, whitespace, ellipsis, exact-width, and nonpositive-width handling. Transcript/table caches invalidate on resize, clear, mismatch, history eviction, and relevant picker/filter changes.
- Zero-project onboarding uses a `projectsLoaded` readiness boundary so delayed startup cannot prematurely show empty-account guidance. Raw and implicit-project JSON omit `error`/`system` roles, trim trailing newlines, skip empty entries, and preserve project metadata.
- Lifecycle plain previews use bounded deterministic canonical JSON-like output while raw `--json` remains complete. Map-key retention, candidate validation, recursion, wide containers, custom marshalers, `IsZero`, `omitempty`/`omitzero`, addressability, and late errors are bounded and encoding/json-compatible. Ambiguous ordering, collisions, cycles, unsupported maps, overflow, or unknowable late errors fail safely as `<unavailable>` rather than retaining payload-sized data or guessing.
- Event command validation rejects unknown modes and extra operands before state changes or requests. One-shot chat/task replies stream stable NDJSON when requested, reconnect at exact UTF-8 offsets, reconcile terminal frames through authoritative status, and fail explicitly on unexpected EOF/deadline/reconnect exhaustion while caller cancellation stays quiet. Identity-less swarm-parent replies return explicit acceptance without speculative duplicate requests.
- Memory output strips terminal controls and bounds lines/documents. Reads reject directory/symlink escapes, revalidate regular-file identity, and use nonblocking no-follow handling so FIFO/replacement attacks cannot block or escape. Search parses each bounded indexed document once into original and normalized forms; the file limit is 8 MiB.
- `.github/workflows/test.yml` keeps vet and coverage independent, uses bounded timeouts and non-empty profiles, awaits status propagation, and gates summaries on success. Manual/reusable uncached runs use `-count=1`; routine push/PR coverage may use Go's successful-test cache.
